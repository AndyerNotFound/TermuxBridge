# Background footprint: removing wasted wakeups + event long-polling

## Measured footprint first

| Metric | Value |
|---|---|
| PSS | **18.5 MB** (Java heap 5.5 MB) |
| RSS | 108 MB, almost entirely shared `.art`/`.oat` pages |
| Idle CPU | 0.0% (0.24 s cumulative) |

Memory and CPU were already low; the real waste was **wakeups**.

## Changes

1. **Accessibility no longer subscribes to content changes by default.**
   `onAccessibilityEvent` was an empty implementation yet subscribed to `typeWindowContentChanged`.
   Measured over 20 scroll gestures: 1036 content events before, **0** after.
   Runtime toggle: `tbridge acc.events both` (enable), `acc.stats` (counters).

2. **`overlay.events` supports long-polling.**

   ```bash
   tbridge overlay events --since 42 --wait 20
   ```

   Suspends when there are no new events (max 25 s), returns immediately when there are. The daemon now uses this instead of interval polling and fully sleeps while idle.
   Measured: empty wait returns at exactly 2.00 s; a click at 3.4 s returns at 4.16 s (including the 280 ms tap disambiguation).

3. **Default subscription mode persisted in XML**: `typeWindowStateChanged` only.

## Unchanged

`flagRetrieveInteractiveWindows`, `canTakeScreenshot`, `canPerformGestures` are all kept — screenshot, gestures, and UI tree export depend on them; removing any would lose features.
