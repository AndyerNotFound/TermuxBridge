## Added

- **IME (Termux keyboard)**: `BridgeImeService`, a minimal IME with a built-in QWERTY + numeric keypad that also accepts text injected from Termux.

  ```bash
  rish -c "ime enable lll.bridge.termux/.BridgeImeService"
  rish -c "ime set lll.bridge.termux/.BridgeImeService"
  tbridge-ime status|commit TEXT|show|hide|pick
  ```

  Verified: injecting `hello from termux` (17 chars) lands in the target EditText. On targetSdk 36, `Settings.Secure.enabled_input_methods` is unreadable; status now uses `InputMethodManager.getEnabledInputMethodList()` + a live service-instance check.

- **App icon**: generated from a photo, center-cropped to square, 5 mipmap densities (APK 62 KB → 225 KB; the icon accounts for most of it).

- **Gallery/video listing**: `tbridge-media image|video [N]` returns name/size/date/w/h/path/uri, newest first. Requires `pm grant lll.bridge.termux android.permission.READ_MEDIA_IMAGES` (same for video).

- **System roles**: `tbridge-role list` reports availability/holding for dialer/sms/home/browser/assistant; `tbridge-role request <role>` opens a foreground page and requests. Note: `RoleManager.createRequestRoleIntent` only works for apps with the matching intent filters — this app has none, so the system silently shows nothing. Becoming a real default browser/dialer/SMS app means implementing those apps.

## Capability boundaries (explicitly not implemented)

- **TTS engine provider**: needs a real synthesizer (eSpeak/Pico or cloud); pure Java cannot synthesize speech. The existing `tts` command is a client, not an engine.
- **Installer provider**: `rish` already provides `pm install`; reimplementing it has no value.
- **Bank card emulation (NFC/HCE)**: will not do. HCE requires card-network-certified AIDs and key hierarchies; emulating payment cards is a fraud/compliance red line. NFC tag reading would be feasible with extra hardware session work.
