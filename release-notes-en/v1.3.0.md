## Added

- **In-place overlay updates** (`overlay.update`): for a window with the same id, diffs the view tree — text/color/progress/padding and child add/remove are applied in place, no window remove+add, so no flicker and no focus steal. Window-level params `x/y/w/h/blur/gravity` can be updated in the same call (via `updateViewLayout`). Returns `{"in_place":true,"ms":0}`; full rebuild only when the structure is incompatible (`in_place:false`).

  Measured on device (same 3-node card, 5 consecutive refreshes):

  | Path | Time |
  |---|---|
  | Rebuild (`show`) | 29 / 12 / 20 / 19 ms |
  | In-place (`update`) | 4 / 1 / 1 / 0 ms |

- **Drag vs. swipe disambiguation**: hold + move beyond 20 dp → `drag:start` → `drag:move` (~40 ms apart, cumulative dx/dy/ms) → `drag:end`. Release with <250 ms and >56 dp of travel → `swipe:left|right|up|down`. Measured: 250 px/400 ms → 8 drag events; 250 px/120 ms → `swipe:right`.
- **Window dragging**: `{"drag_window":true}` — drag the whole overlay by its blank area (verified 64,776 → 205,964 px).
- **Debugging**: `overlay.tree <id>` dumps the view tree (node ids, class names, screen coordinates, sizes); node ids are stored in View tags. Use with `overlay.bounds` to debug coordinates.

## Notes

The "button not clickable" report in the previous release turned out to be wrong test coordinates (wrap-width button 279 px, tapped the blank right side). `overlay.tree` was added to make such issues self-diagnosable.
