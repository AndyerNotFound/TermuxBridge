## Changed

- **App icon**: replaced with a geometrically generated `>_` prompt (dark rounded square + cyan), reproducible via `tools/make_icon.py`, no external image assets. APK 230 KB → **91 KB**.

## Fixed

- **Status bar overlap**: targetSdk 36 enforces edge-to-edge and `MainActivity` drew its title under the status bar. Now consumes systemBars / displayCutout / ime insets via `setOnApplyWindowInsetsListener`; the title sits below the status bar and content moves up when the IME opens. Overlay windows were never affected: `APPLICATION_OVERLAY` coordinates already start below the status bar (measured `y=0` → 141 px). Added clamping: negative `x/y` are not allowed; drag and `update` clamp to the visible area (`y=-500dp` → 141 px).

- **Accessibility text write**: `text.set` / `text.get` / `text.debug` use `ACTION_SET_TEXT`, so **no IME switching is needed**. Verified with Fcitx5 as the default keyboard: 8 chars written and read back. When `getRootInActiveWindow()` misses the target, the service now walks `getWindows()` for editable nodes.

- **Event cursors** (diagnosis for "AI can click the overlay, I can't"): `overlay.events` used to drain on read, so multiple readers (daemon + human) stole events from each other. Every event now carries `seq`:

  ```bash
  tbridge-overlay events 0        # read all, do not drain
  tbridge-overlay events 5        # only seq > 5
  tbridge-overlay events 0 true   # legacy draining behavior
  ```

  Omitting args keeps the old semantics; responses include `last_seq`.

## Touch diagnostics

Pressed nodes flash to alpha 0.55 and `TBridgeTouch` logs include `flags`, to distinguish "touch never arrived" from "event was consumed elsewhere".
